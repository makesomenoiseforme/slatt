19.10.3026. Версия спецификации 0.3. Здесь — краткая сверка обсуждения; подробный источник решений — [реестр](product-decisions.md), функции — [карта](functionality.md), поведение — [правила](functional-rules.md). ## Подтверждённый каркас

| Область | Согласовано |
|---|---|
| Роли | Преподаватель организует работу и подключает семью; ученик/родитель не обязаны регистрироваться до начала работы преподавателя |
| Предметные карточки | Отдельная карточка «ученик + предмет», единая личность/аккаунт; цель необязательна; есть пауза с сохранением истории и разбором уже запланированных встреч |
| Семья | Несколько детей у родителя, общий календарь; несколько подтверждённых взрослых на ребёнка с отдельными аккаунтами и правами; ограниченный отзывной просмотр конкретной связи без регистрации, действия после входа |
| Подключение родителя | Приглашают преподаватель или ученик; родитель принимает приглашение и входит; приглашение ученика требует подтверждения преподавателя перед открытием данных |
| Календарь | Интерактивный; только связанные участники видят разрешённые слоты; длительности выбираются из разрешённых преподавателем; запрос держит слот до ответа максимум 24 часа, но не позднее границы до начала; конкретный интервал открыт |
| Серии и переносы | Дни недели, время, начало и необязательный конец серии; изменение одной или этой и следующих встреч; ученик/родитель могут запросить перенос, до подтверждения преподавателем исходный урок сохраняется |
| Занятие | Общая сущность с доступом по роли; индивидуальное название из предмета и имени/фамилии, групповое — из предмета и группы; тема необязательна; проведение подтверждает преподаватель |
| Отмена/пропуск | Различаются; последствия по заранее установленным условиям показываются до отмены; подтверждение «не приду» сразу отменяет участие и освобождает индивидуальный слот; финансовое согласование отдельно, по времени сообщения и прежним условиям |
| Домашние работы | Работа в предметной карточке, урок необязателен; несколько работ у урока; отмена встречи сохраняет ответы; срок необязателен; сдача целиком/по вопросам; попытки и версии сохраняются; при изменении начатой работы повторно отвечают на затронутые вопросы |
| Проверка | Оценка необязательна; короткие ответы проверяются автоматически, развёрнутые — преподавателем; показ результата настраивается, по умолчанию сразу; готовый правильный ответ по умолчанию скрыт |
| Исправления и AI | Повторные попытки по настройке, по умолчанию свободные; AI-подсказки по настройке работы, по умолчанию включены после попытки/затруднения; обычный вопрос преподавателю сохраняется |
| Вне Slat | Преподаватель может отметить проверенную в тетради/на уроке работу с явной пометкой источника, без вымышленной цифровой сдачи |
| Проверка фото и основания | Пометка конкретного места, привязанный комментарий и версии исправлений; первая попытка, помощь, исправление и наблюдение преподавателя различаются; правильный ответ после помощи не доказывает самостоятельность |
| Библиотека | Личная и общая; папки/теги; разрешённая адаптация личной копии; публикация вкладов в общую базу после модерации содержания, источника и прав |
| Учебные итоги | Личная заметка после урока закрыта; итог семье отдельно. Сводка за период готовится по запросу/расписанию черновиком и публикуется после подтверждения; учебное содержание общее ученику и родителю, без финансов и личных разговоров |
| Содержание сводки | Что изучали, что получается самостоятельно, трудности, следующий шаг, необходимость участия родителя; выводы с основаниями при их наличии, без выдуманного единого процента знаний |
| Общение | Личные разговоры разделены; групповой чат включается преподавателем, имена участников видны; личные работы и расчёты закрыты. Преподаватель задаёт часы/обычный срок ответа; есть очередь вопросов, уведомления сразу/подборкой |
| Расчёты | Отдельные занятия, пакеты занятий/часов, фиксированный период; частичная оплата; остатки раздельны по предметам с общим обзором; напоминания плательщику; неплательщик не видит суммы |
| Пакеты/цены | Срок пакета необязателен; новая цена с даты и уведомлением; купленные пакеты и прошлые начисления сохраняют условия; изменение согласованных будущих уроков — одним подтверждением семьи |

## Существенные открытые решения

1. **Текущий контекст / Learning Memory:** состав, источники, устаревание и необходимость отдельной возможности. История и личные заметки уже предусмотрены, большая автоматическая модель знаний не утверждена.
2. **Детальные расчёты:** фиксированный период, последствия паузы, просрочка, частично оплаченный пакет, возвраты и остаток после окончания срочного пакета. Поддержка схем не означает согласование всех формул.
3. **Границы календаря:** минимальное время до записи, резерв при близком начале урока, срок ожидания переноса и финансового согласования отмены, конфликты серии и внешних календарей, буферы.
4. **Группы:** история чата/материалов для вступивших и вышедших, отмена участия отдельного ученика, персональные исключения.
5. **Участники и доступ:** подтверждение личности, связывание карточек разных преподавателей, права нескольких взрослых, их выдача и отзыв, права после прекращения занятий.
6. **Материалы:** конкретные разрешения для официальных источников, процедура модерации/обновлений, права на файлы преподавателя после завершения связи.
7. **Общий семейный обзор:** агрегация нескольких независимых преподавателей, неполные данные и доступные основания сводок. Одному преподавателю не открываются данные другого.
8. **Модель и реализация:** монетизация Slat, платёжный провайдер/движение денег, разрешённые AI-данные и конкретные интеграции; технический стек не выбран.

Эти вопросы имеют разный масштаб: продуктовые развилки требуют обсуждения, детали интерфейса можно предложить в макетах, доступность внешних функций требует отдельной проверки источников. Список не является препятствием для проектирования экранов.

## Повторная проверка

[Аудит продукта от 19.10.2026](product-audit.md) обсуждён с пользователем: приняты необязательная связь работы с уроком, несколько взрослых, немедленная фиксация отмены участия отдельно от финансов, граница резерва до начала, предметная проверка фото и различение помощи в сводке. Минимум обязательных действий подтверждён; точные пресеты, навигация домашки и одинаковые права взрослых предложены для детализации. Отдельная следующая задача — импорт существующей практики (так пользователь уточнил смысл онбординга); источники и форматы ещё не выбраны.

## Следующий рабочий результат

**С: требование к качеству.** Пользователь готов потратить больше времени ради проработанного продукта; шаблонный «нейрослоп» неприемлем. Конкретный стиль пока не выбирается, текущая задача остаётся продуктовым проектированием. При последующей работе над интерфейсом нужны цельность и удобство реальных сценариев, а не только презентационных экранов.

По результатам практической проверки пользователем российские аналоги исключены из ориентиров проектирования. Западные продукты можно изучать по конкретным сценариям. **П:** удобство решений Slat проверять сравнением времени, количества ручных действий, повторного ввода и ошибок с привычной работой в заметках, календаре и таблицах. Наличие похожей функции у конкурента не является достаточным основанием её добавлять.

Проработать импорт существующей практики: пользователь именно это имел в виду под онбордингом — учеников, материалов и связанных данных. Источники, форматы, сопоставление, проверка дублей и конфликтов ещё открыты; расписание и начальные остатки предложены как часть переезда. Знакомство трёх ролей с интерфейсом не является текущим запросом. Раздел «Домашние работы» вызывает сомнение из-за перегрузки и остаётся открытым: предлагается сравнить его с выдачей/историей внутри предметных карточек и очередью только требующих проверки работ на главной. Одинаковые полномочия двух взрослых также остаются предложением.

Предложение: проверить [14 сквозных сценариев](functional-scenarios.md) на связанной структуре «главная преподавателя → предметная карточка → календарь/занятие → работа → проверка → опубликованный итог», затем сопоставить представления ученика и родителя. Подготовить состав экранов, переходы и пустые состояния. Это продолжение проектирования, не начало разработки и не утверждение всей навигации.
